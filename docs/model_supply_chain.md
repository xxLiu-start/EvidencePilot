# Production model supply chain and BGE-M3 acceptance

Production embedding and reranking require administrator-provisioned absolute local model directories, pinned 40-character upstream revisions, local-files-only mode, and independently trusted SHA-256 digests of manifest.json. Mount bundles read-only and disable network egress during inference.

## Official model compatibility

The official BAAI/bge-m3 repository at revision 5617a9f61b028005a4858fdac845db406aefb181 publishes its XLM-RoBERTa backbone as pytorch_model.bin and auxiliary sparse/ColBERT heads as .pt files. EvidencePilot currently implements Dense-only BGE-M3. It does not load Sparse or ColBERT heads. The official Dense pooling method is CLS pooling followed by L2 normalization; the existing NativeEncoder dense path uses this pooling. The required production compatibility step is therefore a safe, audited conversion of the backbone checkpoint to Safetensors, not a change to CLS pooling.

Run scripts/prepare_bge_m3_bundles.py in a disposable network-enabled model-preparation environment. It pins the official revisions, verifies the upstream checkpoint SHA-256, loads the PyTorch checkpoint with weights_only=True, rejects non-tensor payloads, writes model.safetensors, reads it back and checks every tensor for exact equality, then deletes the source .bin. Sparse/ColBERT .pt files are intentionally excluded because the application does not expose those modes.

The separate official BAAI/bge-reranker-v2-m3 repository publishes model.safetensors. It is a multilingual XLM-R sequence-classification cross-encoder, not the BGE-M3 embedding model. The preparation script pins and verifies its model file SHA-256 independently.

The generated manifest records the exact upstream revision and SHA-256 for every allowed file. The manifest's own digest must be copied into trusted deployment configuration through a separate administrative channel. Do not treat a digest generated by the same untrusted download process as an independent trust anchor.

## Run model smoke acceptance

After preparing bundles, configure:
- EMBEDDING_MODEL=/absolute/path/embedding
- EMBEDDING_REVISION=5617a9f61b028005a4858fdac845db406aefb181
- EMBEDDING_MANIFEST_SHA256=<independently reviewed manifest digest>
- RERANKER_MODEL=/absolute/path/reranker
- RERANKER_REVISION=b9a8f459d786a86f171264d4b075572506495226
- RERANKER_MANIFEST_SHA256=<independently reviewed manifest digest>
- ENVIRONMENT=production
- EMBEDDING_LOCAL_FILES_ONLY=true and RERANKER_LOCAL_FILES_ONLY=true

Run python -m scripts.model_acceptance. This checks actual local model loading, 1024-dimensional normalized dense vectors, finite outputs, a simple semantic ordering smoke test, and the separate reranker. It is not a full retrieval benchmark.

## Run retrieval quality benchmark

Prepare held-out JSONL files:
- queries.jsonl: {"id":"q1","text":"..."}
- corpus.jsonl: {"id":"d1","text":"..."}
- qrels.jsonl: {"query_id":"q1","doc_id":"d1","relevance":2}

Use human-judged relevance labels and keep train/dev/test splits separate. Run python -m scripts.retrieval_quality_benchmark --queries evaluation/bge_m3/queries.jsonl --corpus evaluation/bge_m3/corpus.jsonl --qrels evaluation/bge_m3/qrels.jsonl --output reports/bge_m3/retrieval_metrics.json. The script compares BM25, Dense, RRF Hybrid and Hybrid+Reranker without mutating the original benchmark evaluator or production index. Report Recall@10, MRR@10 and NDCG@10. For public multilingual evaluation, use the official MIRACL or MLDR test splits and cite the exact dataset revision.

## Release gates

A smoke test is not a quality benchmark. A small local fixture is not a substitute for a held-out public or business qrels dataset. Record model revisions, artifact hashes, dataset revision, package lock, hardware, latency percentiles, and bootstrap confidence intervals. Do not claim quality improvements without measured results.

Model runtime isolation, container scans, actual corporate IdP validation and independent human security sign-off remain separate release gates.
